# ByteBot 성장과 도감

**한국어** | [English](bytebot.md)

ByteBot은 Tokeni Bar가 확인한 에이전트 토큰 사용량으로 성장하는 로컬 픽셀
동반자입니다. 별도의 계정이나 서버가 없으며 성장, 등급, 도감과 천장은 모두
Mac에 저장됩니다.

## 성장 에너지

오늘 여러 제공자의 확인된 토큰 증가분을 중복 지급 없이 합산한 값을 `T`라고
할 때 오늘의 성장 에너지는 다음과 같습니다.

```text
T = 0  → 0
T > 0  → floor(32 × log2(1 + T / 25,000))
```

일일 상한은 없습니다. 토큰을 더 사용하면 성장 목표가 계속 올라가지만,
초고사용량 구간에서는 에너지 1에 필요한 추가 토큰이 늘어납니다.

| 오늘 토큰 | 오늘 에너지 |
|---:|---:|
| 10,000 | 15 |
| 25,000 | 32 |
| 50,000 | 50 |
| 100,000 | 74 |
| 250,000 | 110 |
| 500,000 | 140 |
| 1,000,000 | 171 |

같은 누적값은 새로고침해도 한 번만 반영됩니다. 토큰 집계가 줄어들거나
초기화되어도 이미 얻은 에너지와 펫 진행은 회수하지 않습니다.

## 성장 단계

| 단계 | 필요한 누적 에너지 |
|---|---:|
| 알 | 0 |
| 부화 | 80 |
| 주니어 | 280 |
| 성체 | 800 |

성체 이후 얻는 에너지는 해당 ByteBot의 **친밀도 에너지**가 됩니다. 친밀도는
등급 확률을 높이지 않으며, 여정을 마칠 때 개인 최고 기록으로 도감에 남습니다.

작업 중, 쿼터 경고, 토닥하기, 장시간 비활동에 따라 스프라이트 동작이 바뀝니다.
활동 감지는 동작에만 사용하며 성장 에너지를 만들지는 않습니다.

## 등급과 진화

등급은 `일반 → 희귀 → 영웅 → 전설` 순서이며 내려가지 않습니다. 부화, 주니어,
성체 진화 때마다 현재 등급 이상을 판정합니다.

| 현재 등급 | 유지 | 희귀 | 영웅 | 전설 |
|---|---:|---:|---:|---:|
| 일반 | 75.0% | 21.0% | 3.8% | 0.2% |
| 희귀 | 86.0% | - | 13.0% | 1.0% |
| 영웅 | 97.0% | - | - | 3.0% |
| 전설 | 100% | - | - | - |

천장이 없을 때 일반 알에서 시작한 성체의 최종 분포는 일반 42.2%, 희귀 40.9%,
영웅 15.5%, 전설 1.4%입니다.

낮은 등급이 오래 이어지는 상황을 막기 위해 완성한 성체를 기준으로 다음을
보장합니다.

- 최대 3세대 안에 희귀 이상
- 최대 7세대 안에 영웅 이상
- 최대 16세대 안에 전설

천장은 도감에서 남은 최대 세대 수로 확인할 수 있습니다. 중간에 새 알로
다시 시작해도 기존 천장은 유지되지만 앞당겨지지는 않습니다.

## 도감

초기 도감은 13개 외형으로 구성됩니다.

- 공통 알 1개
- 부화·주니어·성체의 4등급 외형 12개

진화에서 직접 본 외형은 **만남**으로 기록됩니다. 높은 등급이 늦은 단계에서
처음 나왔다면 같은 등급의 이전 단계 외형도 **계보**로 해금됩니다. 따라서
전설이 성체에서 처음 나와도 전설 부화와 주니어 외형을 함께 볼 수 있습니다.

메뉴의 격자 버튼 또는 **설정 → Tokeni → ByteBot 도감 열기**에서 다음을
확인할 수 있습니다.

- 13개 외형의 해금 상태
- 실제 만남과 계보 해금 구분
- 완료한 세대, 최고 등급, 최고 친밀도
- 각 등급 천장까지 남은 최대 세대

## 새 알과 여정 마치기

성체가 되면 현재 모습과 계속 함께하며 친밀도를 올리거나, 여정을 마치고 새
일반 알을 받을 수 있습니다. 여정을 마치면 최종 등급, 친밀도와 천장이 도감에
반영됩니다.

성체 이전에도 현재 성장 에너지를 포기하고 새 알을 받을 수 있습니다.

- 해금한 도감과 기존 천장은 유지됩니다.
- 현재 세대의 성장 에너지는 사라집니다.
- 중도 이별은 완료 세대나 천장 진척으로 계산하지 않습니다.
- 같은 날 이미 사용한 에너지를 새 알에 다시 쓸 수 없습니다.

## 토큰을 반영하지 못하는 경우

Tokeni Bar는 값의 범위와 초기화 시점을 확인할 수 있는 토큰만 성장에 씁니다.
데이터가 없거나 오래되었거나 파서가 현재 CLI 형식과 맞지 않으면 임의의 성장량을
만들지 않습니다.

- Codex와 Claude의 완전한 오늘 누적은 확인된 날짜에 반영합니다.
- Gemini와 Grok의 세션 누적, OpenCode의 전체 누적은 첫 관측을 기준선으로 삼고
  이후 증가분부터 반영합니다.
- 앱이 날짜 경계 동안 꺼져 있어 어느 날의 사용인지 알 수 없는 세션·전체 누적은
  소급 추정하지 않습니다.
- 비정상적으로 큰 증가는 다음 관측에서 다시 확인한 뒤 반영합니다.

상세한 집계와 비용 표시 규칙은 [사용량 표시 안내](usage.ko.md)를 참고하세요.

## 저장과 개인정보

- `companion-state.json`: 단계, 등급, 에너지, 친밀도, 도감, 천장, 상호작용 시각
- `usage-growth-ledger.json`: 토큰 범위별 체크포인트와 날짜별 지급 에너지
- `usage-history.json`: 30일 동안의 집계 사용량·쿼터·비용 기록

펫 상태에는 제공자 이름이나 원본 토큰 합계를 넣지 않습니다. 사용 원장에도
프롬프트, 응답, 인증 토큰, 쿠키 또는 계정 비밀정보를 저장하지 않습니다.
분석 도구나 서버 텔레메트리는 없습니다.
