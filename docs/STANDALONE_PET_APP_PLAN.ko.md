# Tokeni 독립 펫 앱 전환 계획

**한국어** | [English](STANDALONE_PET_APP_PLAN.md)

- 계획 버전: 1.0
- 작성일: 2026-09-02
- 상태: 진행 중

## 진행 현황

| 단계 | 상태 | 결과 |
| --- | --- | --- |
| 0. 결정 고정 | 완료 | 한·영 계획과 문서 색인 추가 |
| 1. 독립 앱 셸 | 완료 | 홈·펫·사용량, Settings 링크, 요약 중심 메뉴바와 macOS CI 검증 완료 |
| 2. 동적 콘텐츠 기반 | 완료 | 확장 가능한 종·팩 ID, 게임 참여 경계, 번들·로컬 자산 소스와 macOS CI 검증 완료 |
| 3. Codex 호환 가져오기 | 완료 | 안전 검증·설치·렌더링·외형 적용·팩 관리와 macOS CI 검증 완료 |
| 4–5 | 대기 | 다중 펫 홈과 마감 작업을 순서대로 진행 |

Docker에서 작성한 변경은 GitHub Actions의 macOS 러너에서 `swift test`, release
빌드, 앱 패키징과 번들 메타데이터 검사를 통과해야 다음 단계의 기준점이 된다.

2단계는 기존 단일 문자열 저장 형식을 유지하면서 외부 종 ID를 무손실 왕복하고,
외부 외형이 부화 확률·성장·도감 분모에 자동 참여하지 않도록 분리했다. 자산
카탈로그는 번들/로컬 소스와 Tokeni Native/Codex V1/V2 형식을 명시적으로 구분한다.

3단계는 로컬 ZIP 사전 검사와 원자 설치, V1/V2 행동 렌더링, 출처·라이선스 관리,
삭제와 대표 펫 외형 적용을 연결했다. 외부 외형 선택은 성장 상태와 분리해 저장하며
종, 성장 XP, 알 확률과 도감 분모를 바꾸지 않는다.

이 문서는 Tokeni를 메뉴바 중심 유틸리티에서 독립 창을 가진 펫 관리 앱으로
확장하는 제품 구조, UX 책임, 데이터 경계와 단계별 커밋 계획을 정의한다.

## 1. 유지할 제품 핵심

Tokeni의 중심은 AI 에이전트 사용을 과장 없이 보여 주고, 검증된 누적 토큰
관측을 펫 성장으로 바꾸는 것이다. 확장 과정에서도 다음 규칙은 바뀌지 않는다.

- 성장 XP는 검증된 누적 토큰 증가에서만 나온다.
- 활동 시간은 행동과 애니메이션에만 영향을 주며 성장을 만들지 않는다.
- 확인할 수 없는 쿼터, 비용과 성장은 추정하지 않는다.
- 펫 상태에는 제공자 이름, 원본 토큰 합계, 프롬프트, 응답과 인증정보를 넣지 않는다.
- 메뉴바, 메인 창과 화면 위 펫은 같은 앱 상태를 사용한다.
- 외형, 희귀도와 외부 팩은 성장 배수나 능력 우위를 만들지 않는다.

## 2. 화면별 단일 책임

같은 설정이나 관리 기능을 여러 화면에 반복하지 않는다.

| 화면 | 책임 | 포함하지 않는 기능 |
| --- | --- | --- |
| 메뉴바 | 현재 상태 요약, 새로고침, 카페인, 메인 창 열기, 설정·종료 진입 | 펫 도감, 알 상점, 상세 설정, 긴 사용량 목록 |
| 홈 | 대표 펫, 성장 대상, 오늘의 사용 상태, 다음 행동을 한 화면에 요약 | 전체 도감 편집, 모든 제공자 설정 |
| 펫 | 보유 펫, 성장 대상, 대표 펫, 알, 도감, 꾸미기, 팩 관리 | 제공자 쿼터 설정 |
| 사용량 | 제공자별 상태, 비용, 히스토리와 데이터 신선도 | 펫 관리 액션 |
| macOS 설정 창 | 제공자, 표시, 알림, 카페인, 시작 프로그램과 고급 옵션 | 도감·보유 펫 관리 |
| 화면 위 펫 | 대표 펫의 반응과 짧은 상태 표현 | 영구 설정과 경제 액션 |

메뉴바에서 제거한 기능은 숨기는 것이 아니라 메인 창의 정확한 목적지로 연결한다.
메인 창에서 다시 메뉴바 전용 빠른 제어를 복제하지 않는다.

## 3. 메인 창 정보 구조

메인 창은 macOS `NavigationSplitView`를 사용한다.

```text
Tokeni
├── 홈
├── 펫
│   ├── 함께 있는 펫
│   ├── 보유 펫
│   ├── 알
│   ├── 도감
│   ├── 꾸미기
│   └── 펫 팩
├── 사용량
└── 설정 → macOS 설정 창 열기
```

첫 단계에서는 기존 화면을 안전하게 재배치하고, 후속 단계에서 펫 화면 내부의 긴
세그먼트를 위 하위 목적지로 분리한다. 하나의 액션에는 하나의 정식 위치만 둔다.

### 홈의 우선순위

1. 대표 펫과 현재 행동
2. 실제 XP를 받는 성장 대상과 다음 레벨/진화
3. 사용량 신선도와 새로고침 상태
4. 진화, 부화, 보상처럼 지금 처리할 수 있는 행동
5. 카페인 상태와 빠른 토글

홈은 모든 수치를 복제하는 대시보드가 아니다. 상세 정보는 해당 목적지로 연결한다.

## 4. 펫 개념과 자산 계층

게임 개체와 그림 팩을 분리한다.

- `CompanionInstance`: UUID, 성장 XP, 단계, 외형, 이름, 성격과 추억을 가진 게임 개체
- `CompanionDefinition`: 안정적인 종 ID, 표시 메타데이터와 지원 기능
- `CompanionAssetPack`: 애니메이션 프레임과 출처·라이선스 메타데이터
- `CompanionAssetSource`: 앱 번들 또는 사용자가 가져온 로컬 팩
- `CompanionRoleSelection`: 대표 펫, 성장 대상과 전시 펫 선택

종 ID는 문자열 기반 값 객체로 전환한다. 내장 종은 정적 상수로 제공하되 외부 팩을
등록하기 위해 앱 재빌드를 요구하지 않는다. 알 확률과 세대 규칙에는 검증된 내장
종만 참여하고, 외부 팩은 기본적으로 게임 확률에 개입하지 않는다.

## 5. 외부 펫 팩 정책

### 지원 모드

- `Tokeni Native`: 유년기·성장기·성체와 Tokeni 행동/외형을 모두 제공
- `Codex Compatible`: Codex Pets V1/V2의 단일 캐릭터 애니메이션을 외형으로 사용

Codex 호환 팩은 없는 상태를 다음처럼 안전하게 대체한다.

| Tokeni 행동 | Codex 상태 | 폴백 |
| --- | --- | --- |
| 기본 | Idle | 첫 유효 프레임 |
| 작업 | Review | Running, Idle |
| 대기 | Waiting | Idle |
| 경고 | Failed | Idle |
| 축하 | Waving | Jumping, Idle |
| 시그니처 | Waving | Idle |
| 수면 | 없음 | Idle 정적 프레임 |

Codex 호환 팩은 단계별 아트가 없으므로 모든 성장 단계에서 같은 외형을 사용하는
`외부 외형`으로 표시한다. 완전한 신규 종으로 승격하려면 Tokeni Native 계약과
검수를 통과해야 한다.

### 가져오기 안전성

- 첫 버전은 사용자가 선택한 로컬 `.codex-pet.zip`만 가져온다.
- 원격 갤러리 API는 불안정한 외부 계약이므로 코어 성장이나 앱 시작에 의존하지 않는다.
- 압축 해제 전에 파일 수, 압축·해제 크기, 경로 탈출과 심볼릭 링크를 검사한다.
- `pet.json`과 단일 `spritesheet.webp` 또는 `spritesheet.png` 외 실행 파일이나
  스크립트를 허용하지 않는다.
- V1 `1536×1872`, V2 `1536×2288`과 매니페스트 버전 일치를 검사한다.
- 검증 실패 팩은 설치하지 않고 구체적인 수정 가능 오류를 보여 준다.
- 설치는 Application Support의 임시 디렉터리에서 검증한 뒤 원자적으로 교체한다.
- 삭제는 펫 게임 상태를 삭제하지 않고 자산 연결을 기본 내장 외형으로 되돌린다.

### 권리와 출처

외부 팩을 다운로드할 수 있다는 사실은 재배포 허가를 의미하지 않는다.

- 외부 팩은 기본 앱 번들에 포함하지 않는다.
- 작성자, 원본 URL, 라이선스 식별자와 고지문을 선택적으로 저장하고 UI에 표시한다.
- 라이선스가 없으면 `미지정 · 로컬 사용`으로 표시한다.
- 공식 제공 팩은 재배포와 파생 작업이 허용된 라이선스를 별도로 검수한다.
- 유명 인물·브랜드·캐릭터 기반 팩은 권리 확인 없이 공식 카탈로그에 넣지 않는다.

## 6. 다중 펫 규칙

- `대표 펫`은 홈, 메뉴바와 화면 위 펫에 표시된다.
- `성장 대상` 한 마리만 새로 검증된 성장 XP를 받는다.
- `전시 펫`은 향후 펫 하우스에서 함께 보이지만 활동 애니메이션만 공유한다.
- 대표 펫과 성장 대상은 독립적으로 선택한다.
- 성장 대상이 만렙이거나 제거된 경우 기존 정책의 안전한 자동 전환을 유지한다.
- 같은 관측에서 여러 펫에게 XP를 복제하지 않는다.

## 7. 상태와 생명주기

`UsageStore`의 기능을 화면별로 복제하지 않는다. 전환 중에는 기존 저장·조정
코디네이터를 유지하고, UI 상태만 별도 프레젠테이션 모델로 얇게 분리한다.

- 앱 시작은 메뉴바 라벨의 등장 여부에 의존하지 않는다.
- 메인 창과 메뉴바가 동시에 열려도 새로고침 루프는 하나만 실행한다.
- 창을 닫아도 메뉴바 서비스와 화면 위 펫은 사용자가 종료할 때까지 유지된다.
- 설정 변경은 한 저장소에 기록되고 모든 표면에 즉시 반영된다.
- 펫 팩 메타데이터에는 사용량이나 제공자 정보를 기록하지 않는다.

## 8. 접근성과 성능

- VoiceOver는 펫 이름, 역할, 단계, 레벨과 가능한 행동을 순서대로 읽는다.
- 키보드만으로 사이드바, 펫 그리드, 가져오기와 확인 창을 사용할 수 있어야 한다.
- Reduce Motion과 저전력 모드에서는 정적 프레임과 비모션 피드백을 사용한다.
- 창이 보이지 않을 때 대형 미리보기 애니메이션을 중지한다.
- 외부 시트는 지연 로드하고 기존 이미지 캐시 상한과 메모리 압력 해제를 유지한다.
- 오류 상태는 사용할 수 없음, 오래됨과 손상을 구분하며 값을 만들어 내지 않는다.

## 9. 단계별 커밋 계획

각 커밋은 관련 테스트와 문서 갱신을 포함하며 가능한 한 독립적으로 빌드된다.
사용자에게 보이는 변경에는 고유한 한·영 `.changes` 조각을 추가한다.

### 단계 0 — 결정 고정

1. `docs: plan standalone pet application`
   - 이 계획과 영문 문서, 문서 색인 추가

### 단계 1 — 독립 앱 셸과 중복 제거

2. `feat: add standalone application shell`
   - 메인 `WindowGroup`, 안정적인 창 ID와 앱 시작 생명주기
   - 홈·펫·사용량 사이드바와 macOS 설정 창 링크
   - 내비게이션 선택과 프레젠테이션 테스트
3. `refactor: focus menu bar on quick controls`
   - 메뉴바를 요약, 새로고침, 카페인, 앱 열기, 설정·종료로 제한
   - 도감·관리 액션은 메인 창 목적지로 연결
   - 중복 액션/메뉴 회귀 테스트
4. `docs: document application navigation`
   - 한·영 README, 사용 문서와 스크린 흐름 최신화

### 단계 2 — 동적 콘텐츠 기반

5. `refactor: introduce extensible companion identifiers`
   - 문자열 기반 종·팩 ID와 내장 상수

   - 번들/가져온 자산 로더와 공통 렌더 계약
   - 누락·손상·메모리 압력 테스트

### 단계 3 — Codex 호환 로컬 가져오기

   - V1/V2 매니페스트, 크기, 행·프레임 계약의 순수 검증기
   - 정제된 정상/실패 fixture 테스트
9. `feat: install local companion asset packs`
   - 안전한 압축 해제, 원자 설치, 목록과 삭제

10. `feat: render imported companion packs`
    - 행동 매핑, 비정사각형 프레임 비율, 폴백과 접근성
11. `feat: add companion pack management`
    - 파일 가져오기, 검증 결과, 출처·라이선스, 삭제 UI

### 단계 4 — 다중 펫 홈

    - 대표·성장·전시 역할과 저장 마이그레이션

    - 전체 Swift 테스트·빌드, 패키징 리소스와 수동 macOS 체크리스트

커밋 수는 테스트 가능한 경계를 지키기 위해 분리하거나 합칠 수 있지만 단계 순서와
책임 경계는 바꾸지 않는다.

## 10. 단계별 완료 조건

각 단계는 다음 조건을 모두 만족해야 완료한다.

- 해당 단계의 도메인 및 UI 테스트 통과
- `swift test`와 `swift build` 통과
- 한·영 사용자 문서가 실제 동작과 일치
- 사용자 노출 변경의 한·영 릴리스 조각 존재
- 기존 저장 데이터가 손실 없이 열림
- 성장 불변 규칙과 개인정보 경계 위반 없음
- 메뉴바와 메인 창에 동일 관리 기능이 중복되지 않음

릴리스 전에는 깨끗한 설치, 기존 설치 업데이트, 손상된 외부 팩, 외부 팩 삭제,
오프라인 시작과 모든 사용량 제공자 불가 상태를 수동으로 확인한다.
