# 승인 후 구현 및 커밋 계획

## 0. 시작 조건

이 문서는 구현 순서를 정의하지만 구현 승인을 의미하지 않는다.
[10-decisions.md](10-decisions.md)의 필수 결정이 확정된 뒤 별도 작업 브랜치에서
시작한다.

각 커밋은 가능한 한 독립적으로 빌드되고 테스트되어야 한다. 모델, 저장, UI,
에셋을 한 커밋에 섞지 않는다.

## 1단계: 공개 규칙과 테스트 가능한 성장식

커밋 1: 성장 도메인 용어와 설정

- `GrowthEnergy`, 새 단계, 등급, 임계점 모델
- 순수 함수 형태의 토큰→에너지 계산
- 단조성, 경계, 오버플로 테스트
- contributor guide의 `활동 분 기반 성장` 규칙을 `검증된 토큰 기반 성장`으로 갱신
- 아직 기존 활동 기반 성장 연결은 유지

커밋 2: 성장 관측 계약

- 제공자 중립 `GrowthUsageObservation`
- 일간/전체/세션 범위와 안정 키
- 대표 관측값 선택 규칙
- shared UI에 제공자 switch를 추가하지 않음

## 2단계: 제공자 관측 정합성

커밋 3: Codex·Claude 일간 관측

- 날짜, 지연, 중복 fixture 테스트

커밋 4: OpenCode 전체 누적 관측

- DB 교체, 감소, 기준선 테스트

커밋 5: Gemini·Grok 세션 관측

- 안정적인 세션 식별자
- 세션 전환과 컨텍스트 초기화 fixture 테스트

모든 제공자가 준비되기 전에는 새 성장 기능을 기본 활성화하지 않는다.

## 3단계: 정확히 한 번 지급

커밋 6: 성장 원장

- 날짜별 체크포인트와 지급량
- 소스 전환, 지연 버킷, 값 감소 처리
- 관측 순서 독립성 테스트

커밋 7: UsageStore 연결

- 새로고침 후 성장 목표 계산
- 기존 활동 시간은 행동 애니메이션에만 사용
- 토큰 미지원/보류 상태 노출

## 4단계: 진화 게임 규칙

커밋 8: 진화와 등급 전이

- 주입 가능한 RNG
- 하락 없는 전이
- 기본 확률 분포 테스트

커밋 9: 천장과 새 세대

- 어덜트 완료 카운터
- 겹치는 보장 우선순위
- 중도 이별은 카운터에 영향 없음

커밋 10: 도감 도메인

- 발견과 완료 기록 분리
- 13개 form ID
- 최근 완료 기록 제한

## 5단계: 저장과 기존 사용자 이전

커밋 11: 스키마 v2와 원자 저장

- 현재 펫·도감·천장 일관 저장
- 어덜트 친밀도와 계보 해금
- 이벤트 ID와 보류 연출
- 손상 파일 폴백

커밋 12: v1 마이그레이션

- 승인된 A/B/C 정책 구현
- 백업과 모든 단계 fixture
- 최초 성장 기준선

마이그레이션 커밋은 에셋·UI 변경과 분리해 데이터 검토를 쉽게 한다.

## 6단계: 오리지널 아트와 렌더러

커밋 13: 매니페스트 v2와 안전 폴백

- stage+rarity 에셋 조회
- 누락/손상 시 앱이 종료되지 않는 테스트

커밋 14 이후: 승인된 에셋 묶음

- Normal 단계 세트
- Rare 세트
- Epic 세트
- Legendary 세트
- 라이선스, 팔레트, 원본 출처 문서

대용량 바이너리 변경은 코드 커밋과 분리한다.

## 7단계: UI와 현지화

커밋 15: 펫 카드와 성장 상태

- 오늘 토큰/에너지, 다음 진화
- 어덜트 친밀도와 개인 최고
- 보류·오래됨·감소 상태
- 어덜트 선택

커밋 16: 진화 연출과 복구

- 저장 후 연출
- 보지 못한 결과 재표시
- Reduce Motion

커밋 17: 도감과 새 알 흐름

- 13칸 그리드
- 발견/완료/천장
- 중도 이별 확인

커밋 18: 설정과 접근성

- 게임 기능 끄기
- 게임 알림 분리
- VoiceOver, 키보드, 저전력

## 8단계: 문서와 릴리스

커밋 19: 공개 문서 최신화

- 한국어·영어 README
- 사용 문서
- 성장 계산, 확률, 천장, 저장 데이터 설명
- 개인정보 경계

커밋 20: 릴리스 준비

- 버전과 변경 기록
- Homebrew 설치/업데이트 재검증
- 패키징 후 13개 에셋 포함 검사
- 깨끗한 설치와 v1 업데이트 경로 확인

## 9. 검증 루프

각 코드 커밋:

```text
swift test
swift build
```

제공자 파서 커밋:

- 정제된 fixture 추가
- 토큰 범위·초기화·세션 전환 테스트

패키징/에셋 커밋:

- 앱 번들 리소스 목록 검사
- Homebrew Formula 테스트
- 번들에서 메뉴를 실제로 열어 폴백 확인

릴리스 전:

- 확률 시뮬레이션
- 마이그레이션 행렬
- macOS 지원 버전 수동 smoke test

## 10. 롤아웃 전략

1. 내부 기능 플래그로 기존 활동 성장과 새 토큰 성장을 동시에 비교하되 한쪽만 지급
2. 개발 빌드에서 날짜별 계산 진단 확인
3. 모든 제공자 관측 준비 후 새 시스템으로 마이그레이션
4. 공개 베타가 없다면 첫 안정 버전에서 보수적 임계점 사용
5. 밸런스 변경은 공식과 임계점을 공개하고 기존 에너지를 삭감하지 않는 방향으로 적용

원격으로 확률을 몰래 바꾸는 설정은 두지 않는다. 확률·천장 변경은 코드, 테스트,
릴리스 노트에 남긴다.
